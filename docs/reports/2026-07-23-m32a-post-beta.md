| Gate decision | REJECTED | **APPROVED** |

The two-order-of-magnitude improvement in drawdown is the direct
consequence of:

1. **OMS VWAP** (B1) — `avg_fill_price` is now volume-weighted, so
   position value is correctly tracked, preventing over-leveraged
   exposure that previously inflated drawdowns.
2. **Ledger notional** (B2) — Cash is debited by `price * quantity` on
   every BUY, so the ledger actually reflects the cash side of the
   trade, preventing the qualification runner from letting positions
   accumulate beyond account capacity.
3. **Idempotency persistence** (B3) — no duplicate fills across the
   run.
4. **Overfill guard** (B13) — cumulative fills are bounded by
   `order.quantity`.

## Caveats

- **G5 is NOT_STARTED** (per ADR-014).  This M32a run is a smoke
  re-run after the OMS/Ledger fixes, not M31 evidence.
- The data source is `ccxt` (BTC/USDT 1h) per the existing
  `run_m32a_paper_sessions.py` defaults.  An ES 1d or 1h run on the
  post-M31 dataset would be a separate M32b.
- The Sharpe of 0.11 is well below any meaningful edge threshold;
  this run is technical gate evidence, not strategy validation.
- Run-to-run variance is significant (5 sessions gave P&L -$33 to
  +$194, see log); 20 sessions is the minimum for stable mean.

## What this run does NOT prove

- That any trading strategy has positive expected value.
- That the system is safe for LIVE execution (still G1-006 PAPER-only).
- That the OMS/Ledger are correct under production load (Postgres,
  network, concurrency).  In-memory state dies across CLI invocations
  unless the SQLite idempotency store is wired explicitly.
- That M31 evidence is reproducible (G5 still NOT_STARTED).
